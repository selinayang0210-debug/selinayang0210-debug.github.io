The premise

The prompt was carrying too much.

Most generative tools compress creative direction into one text field. Style, lighting, material, composition, and camera intent disappear into prose, so people repeatedly rewrite prompts while guessing what the model understood.

I reframed the prompt as the final output of a decision-making process—not the place where every decision must begin.

Product thesis“Prompt is the final output of a decision-making process, not the entry point.”

Interaction principles

A system for visible judgment.

01

Keep language flexible

The brief carries purpose, feeling, and constraints without becoming a rigid prompt formula.

02

Make decisions visible

High-confidence visual choices become inspectable chips with evidence, category, and provenance.

03

Let AI propose

AI can create meaningfully different routes, but it cannot silently change the current direction.

04

Protect confirmation

Every accepted direction becomes a recoverable version whose confirmed choices survive reruns.

Direction + prompt

The direction sits above the prompt for a reason.

Current direction gives visual decisions a persistent, editable place. The prompt underneath carries the subject, purpose, feeling, and constraints that still need language.

01

Decisions you can inspect and edit

Each chip names a visual choice. Hover reveals an example, category, explanation, and Library source; remove a chip or add a Library decision without rewriting the brief.

02

Language with room for intent

The prompt explains what to make and why. In the prototype, entering an exact Library term turns it into an editable chip; open-ended or ambiguous language remains in the text field.

03

One baseline across both modes

Normal Mode uses Current direction for direct generation. AI Mode labels the same choices Confirmed decisions: suggested routes stay separate until the user confirms a version.

Core workflow

AI suggests a change. The user confirms a version.

AI Mode lives inside the same workspace as direct generation. It behaves as a direction assistant, not an always-on chat or an autonomous art director.

Directions are diffs, not snapshots.

The labels under a direction card describe what would change relative to the current baseline. A selection is only a proposal under review; Current direction stays untouched until confirmation.

Preview versus execution

A route preview is not a finished result.

The preview rehearses the proposed visual logic. Only after confirmation does Mize execute a new result from the updated direction, so the user can distinguish exploration from generation.

The knowledge layer

Library is evidence, not inspiration wallpaper.

Each item names one reusable creative decision and proves it with three or four examples. The subject may change; the decision must remain legible across the evidence set.

From category to evidence

Browse a decision, expand its proof, then bring it into the active workspace.

The interaction preserves the distinction between a reusable knowledge item and one concrete example, so users can reference either the rule or the execution.

What the iteration clarified

Control needed to be a state model, not a slogan.

01Show the difference from the current direction.

Why change
Earlier cards presented complete directions, leaving the difference from the current baseline implicit.
Design decision
I changed each proposal into a Keep / Add / Replace comparison, making its relationship to already-confirmed choices explicit.
Trade-off
Cards contain more detail to review. I accepted that extra reading to make the scope of a change clear before commitment.

02Let people inspect a route before committing.

Why change
Selecting an interesting route can mean wanting to inspect it. That should not automatically replace the current direction.
Design decision
Selection marks a proposal for review. Only Confirm updates the current direction and creates a recoverable version.
Trade-off
Confirmation adds a step before generation. Normal Mode keeps a direct Generate path when AI exploration is unnecessary.

Related refinements

  • Separated Library knowledge, Saved bookmarks, and user-owned Assets.
  • Rebuilt the representative task so references, decisions, previews, and results tell one coherent story.

Current outcome

A working front-end prototype for testing the product logic.

The prototype covers Home, Image and Video Workspace, AI direction exploration, direct generation, Library evidence, Assets, Saved, recent workspaces, recovery, and model selection. Model calls and persistence remain simulated so the interaction model can be evaluated before backend investment.
